# 文章博士（Monjo-Hakase）— 現状（as-is）調査

> 調査日: 2026-08-21 / 対象: http://monjo.lunark.org/ および配布ソース `monjo-hakase-r2.zip`
> この文書は「リブート前に引き継いだ旧システムの実態」を固定的に記録したもの。実装が進んでも内容は更新しない（更新すべきは [`to-be.md`](./to-be.md)）。

## 概要

日本語の技術文書・論文向けの **Webベース自動文章校正支援ツール**。フォームに文章を貼ると、係り受け解析にかけて読みにくい箇所を色付きで指摘する。個人開発（作者: Lunar-K / Lunarfactory）のフリーソフトで、ソースも公開されている。

- サービス開始: 2011-11-05（Rel.1）
- 最終更新: サイト本体は 2015-05-21、更新履歴の記載は 2013 年まで、配布 zip は 2013-07-08（Rev.2）
- ライセンス: BSDL / GPL デュアル（同梱 jcorrect が GPL のため）

## 稼働状況

- **CGI は現在も稼働中。** 調査時に通常の校正リクエストを1件送信したところ、約 0.46 秒で正常に結果を返した。校正エンジンは今も生きている。
- サイトの見た目・文言・お知らせは 2013〜2015 年で更新停止。実質「化石サイト」。
- ホスティング: さくらインターネットの VPS（大阪、IP 160.16.54.201）。
- Web サーバ: Apache/2.4.52 (Ubuntu)。
- **HTTPS は無効**（443 番ポートは接続拒否）。**HTTP 平文のみ**で、フォーム送信文が暗号化されない。

## アーキテクチャ

Perl CGI（`njc.cgi`）が、外部コマンドを順に呼ぶパイプライン構成。

```
ユーザー入力（txtInput, multipart/form-data POST）
  │  サニタイズ（全角化）＋改行正規化
  ▼
一時ファイル /tmp/jcorrect$$ に書き出し
  │
  ├─▶ nkf -w（UTF-8変換） | jcorrect-hs（/var/www/jcorrect-hs）
  │        └─ 主語なし・冗長表現・語順エラーを判定（内部で CaboCha を IPC::Open2 で呼ぶ）
  │
  └─▶ 各文ごとに  echo <文> | cabocha -f1
           └─ 係り受けの深さ・量を評価
  ▼
7種類のエラーに分類して HTML 表示（色付きハイライト＋一覧＋解説）
```

### 検出する 7 エラー

| # | 種別 | 判定基準 |
|---|------|----------|
| 1 | 主語なし | 係り受け解析で主語が検出できない |
| 2 | 冗長表現 | jcorrect の接続詞ベース辞書ルールに合致 |
| 3 | 語順エラー | 係り受けの語順が逆転 |
| 4 | 文節長さ超過 | 文節が 30 文字以上 |
| 5 | 1文長さ超過 | 1 文が長すぎる |
| 6 | 係り受け量過多 | 1 文節への係り受けが多すぎる |
| 7 | 係り受け長さ冗長 | 係り受けが係り先を含め 5 段以上 |

設計思想は「機械が係り受けを解析できる文 ＝ 分かりやすい文」。エラーを潰すほど技術文として読みやすくなる、という前提。

## 既知の問題・負債

### セキュリティ

- **HTTP 平文のみ（TLS 無し）。** 送信文が盗聴可能。
- **シェルコマンドインジェクションの余地（CWE-78）。** `njc.cgi` の入力サニタイズ（921〜928 行付近）は `< > ( ) & ; ' "` を全角に置換するが、**バッククォート `` ` `` ・パイプ `|` ・`$` を無害化していない**。その状態で 950 行目が

  ```perl
  @paCaboCha=`echo $gaStatement[$pLine] | $cpCABOCHA -f1`;
  ```

  と、ユーザー入力由来の文字列をバッククォート（シェル経由）へ直接展開している。バッククォートが素通りするため任意コマンド実行につながり得る。
  ※これは公開 GPL/BSD ソースの静的解析による指摘。稼働サーバへの攻撃検証は行っていない。
  - 参考: jcorrect-hs 側は `IPC::Open2` でリスト形式引数で CaboCha を呼んでおり、こちらは安全な作法。njc.cgi の `echo`＋バッククォートを同様の方式に置き換えるのが修正の勘所。
  - なお jcorrect 実行（939 行 `` `$cpNKF -w $cpTMPFILE | $cpJCORRECT` ``）は入力を一時ファイル経由で渡しており、パス自体はユーザー制御でないためこの箇所は相対的に低リスク。

### 保守性・鮮度

- 死んだ第三者ウィジェット多数: 忍者ツールズ（shinobi.jp）ボタン、はてな/Yahoo! ブックマークボタン、埋め込み BBS（seesaa の web-sozai、`bbs-u3/` は生存）。
- 旧式 Google Analytics（`ga.js` / UA-27485278-1）。Universal Analytics 以前の実装で現在は計測不能。
- 外部リンク切れ多数（`code.google.com/p/cabocha`、`flavors.me` 等、サービス自体が終了）。
- Perl CGI・グローバル変数多用の手続き型コードで、テスト無し。

## リブートに向けた論点（詳細は to-be.md）

- TLS 化（HTTPS 必須化）
- コマンドインジェクションの解消（`echo`＋バッククォート → リスト引数呼び出し）
- 死んだトラッキング/ウィジェットの除去
- 解析エンジン（CaboCha / MeCab / jcorrect）の現行バージョン対応、またはエンジン刷新の検討
- 実行形態の見直し（Perl CGI のまま vs API サーバ + フロント分離 vs コンテナ化）
